# 阅读混合检索与 OCR 人工校正

客户端仍是 Tauri 2 + Rust Axum，运行时不启动 Python 或 Node。阅读资料、SQLite
版本记录、向量、页图和审核记录全部使用安装目录中的便携路径。

## 使用方式与数据发送

- 默认只在当前阅读资料集内使用本地关键词检索，搜索范围不受阅读视口页码限制。
- 在设置的“向量模型”页面，或阅读器的“阅读检索设置与索引状态”中开启混合检索。
  首次开启必须明确确认：资料文本和查询问题会发送给用户配置的向量服务并可能计费。
- 开启后当前资料集立即建立索引，其他资料集首次打开时建立。未配置模型、
  索引尚未完成、服务故障或维度不匹配时，继续返回关键词结果及降级原因。
- “更新索引”增量补建当前资料集，保留已完成且模型、文本未变化的页面；“关闭并删除当前索引”先关闭全局自动建立，
  再移除当前资料集成员的向量。共享材料的其他资料集也会在下次开启检索后补建。
- 变更服务地址、配置 ID、模型 ID 或模型标识会改变索引签名，旧签名向量不参与新模型查询。
- 向量模型已保存但默认项为空时，自动采用唯一的有效模型，不要求额外点击“设为默认”。
  如果存在多个候选，请在设置 → 向量模型将其中一个设为默认；失效的显式默认项或提供方引用
  会显示具体原因，不擅自切换账户。阅读器同时显示实际采用的模型名称。
- 修复配置后重新打开资料集或点击“更新索引”即可重试，排队期间不继续显示上一次失败的错误。

## 检索实现

`reading_index.rs` 复用模型目录的提供方关联解析，严格使用用户设置地址与额外请求头。
不回退 OpenAI 官方地址，默认不发送 `dimensions`。支持 OpenAI 兼容、Ollama 与
Cohere 批量响应；校验乱序序号、数量、维度、有限数值及非零范数。单批最多 32 条。

### 向量请求节流和恢复

- 同一服务地址和凭据的阅读索引、查询、不同模型及资料集共用一个请求节流器，同一时刻
  只发送一个请求；成功请求之间至少间隔两秒，约不超过每分钟 30 次，不按每页重置。
- 429 后按 5、10、20、40 秒指数退避，最多额外重试四次；兼容 `Retry-After`
  的秒数和 HTTP 日期，等待时间不早于服务端要求。每次 429 将后续正常间隔加倍，
  最高 30 秒，当前进程内保留降速结果。5xx 最多额外重试三次，也遵守服务端等待头。
- 索引请求超时 60 秒。对话查询超时 15 秒，不重试 429/5xx；冷却期间直接使用关键词，
  等待其他向量请求最多两秒，避免对话长时间卡在后台索引的重试队列中。
- 等待期间显示“等待向量服务”、原因和预计继续时间；等待、队列、网络请求均可取消。
  失败保留完成页数、总页数、模型和签名，不把限流误报成未配置模型。
- 单页完成后立即持久化。再次点击“更新索引”或重启后续建，只发送缺失、文本变化或
  模型签名变化的页面，避免失败后反复重传整本资料。持续 429 也可能来自额度不足，
  达到重试上限后停止并提示检查提供方配额，关键词检索保持可用。

每个定位单元单独切段，优先自然段及句子边界，目标 800–1200 字符、上限 1600、
重叠 120，不跨物理页。普通页直接嵌入全文；超过 8000 字符的长页用全部段落向量
的归一化均值构造页向量，避免截断页尾。纯页图标记不作为 OCR 正文建立向量。

页向量取 12 个候选，段落取 32 个，关键词取 32 个；以 RRF（k=60）融合，
权重分别为 1.0、1.2、0.9。同一页在同一路径只投一次票，防止长页凭段落数量霸榜。
返回材料 ID、版本、定位号、文字偏移、来源方式和片段，引用前仍需读取原文核对。
向量使用 SQLite float32 BLOB，Rust 只缓存当前资料集成员的向量，以归一化余弦检索排序。

## 校正与版本

1. PDF 导入保留原件、首次提取文本、文本来源和已生成页图。超过导入预览范围的
   页面按需原生渲染，生成图片不会重新运行 OCR。
2. `view_figure` 接受图片名或 PDF 物理页 `locator`，对照当前提取文本看图，并保存
   当前用户、回合、会话、材料版本、模型与页图哈希绑定的 `evidence_id`。
3. 模型发现错误或可改善之处后显式调用 `propose_ocr_correction`。服务验证依据来自
   本回合和当前材料版本，再保存原 OCR、修改前文本、模型建议、模型配置 ID、
   模型标识、提示词版本、时间、自报置信度与差异摘要。重复建议幂等。
4. 阅读器展示待审核数量、对应页面、原图及原 OCR。用户可编辑整页建议，逐页确认
   或拒绝；模型没有接受建议的工具。自报置信度不是经校准的识别准确率。
5. 确认请求必须携带 `expected_revision`，同时检查建议基础页文本是否仍然一致。
   使用 SQLite `BEGIN IMMEDIATE` 原子提交材料版本、差异页快照、确认文本、
   审核状态和向量失效记录。旧版本只追加变更页，读取时继承此前未变更页；
   原始 OCR 也只在基线元数据中保存一次，避免从元数据重复存储整本原文。
6. `units.json` 保留首次提取结果；有版本记录后，以 SQLite 当前版本为检索和
   阅读工具的文本权威，避免文件写入失败形成版本指针与正文不一致。
7. 仅被修改页面的页向量和段落向量失效、重新请求嵌入。其他页复用既有向量，
   索引期间再次修改会排队补建，网络返回后的旧文本向量不会写入当前页。
8. 保留旧标注和引用，按原文、前后文及位置选择器重新校验。唯一命中迁移到新版本，
   否则标记 `unresolved`、`ambiguous` 或 `stale`。失效矩形留备份但不绘制。
   点击无法确认的旧引用时展示历史原文与当前文本，允许用户打开当前页核对。

数据库迁移为幂等附加迁移。旧资料首次打开、索引或被引用时才建立基线快照，不改变原文件。
每个用户使用自己的数据库与安装目录子路径，不跨资料集搜索其他材料。

## 接口

以下路径均位于 `/api/reading`，沿用客户端现有用户与工作区作用域验证。

| 方法与路径 | 行为 |
| --- | --- |
| `GET/PUT /retrieval/settings` | 全局开关、明确发送确认、可选当前 `workspace_id` |
| `GET/POST/DELETE /workspaces/{id}/index` | 状态、增量补建或断点继续、删除索引 |
| `POST /workspaces/{id}/search` | `query`、可选 `material_id` 与 `limit`；返回融合结果 |
| `GET /materials/{id}/pages/{locator}/image` | 按需页图地址和 SHA256 |
| `GET /materials/{id}/ocr-corrections` | 待审核数量与完整审核历史 |
| `POST /materials/{id}/ocr-corrections/{cid}/accept` | `expected_revision` 与可选用户编辑 `text` |
| `POST /materials/{id}/ocr-corrections/{cid}/reject` | 拒绝待审核建议 |
| `GET /materials/{id}/revisions` | 实际历史版本及完整单元数 |
| `GET /materials/{id}/revisions/{rev}/units/{locator}` | 指定版本的真实文本，未知版本返回 404 |
| `POST /materials/{id}/references/resolve` | `revision`、`locator`、可选 `quote/selectors`，返回重新校验结果 |

## 验证

Rust 测试覆盖批量向量乱序、坏向量、中文切段、自定义网关关联覆盖旧官方地址、
关键词降级、跨材料越界拒绝、单页增量更新、审核依据、重复建议、版本冲突、
用户编辑、原件不变、历史快照、标注重新定位和重启后的幂等迁移。
前端测试覆盖首次开启的确认步骤、逐页审核、编辑文本提交、版本冲突和拒绝操作。

`node scripts/verify_reading_hybrid.mjs` 使用最终发行 EXE 的干净副本、本地模拟网关和
121 页 PDF，检查第 100 页视口下定位第一页、第 121 页按需渲染、真实对话看图及建议、
真实界面编辑确认、其他 120 页向量逐字节不变、旧引用及标注、重启持久化。
同时覆盖唯一模型未设默认、配置应用后从失败恢复、多模型歧义不发送请求、
明确默认选择，以及阅读器实际显示所用模型。报告与审核截图位于 `artifacts/reading-hybrid-verification`。
模拟视觉服务仅验证工程流程，不代表真实视觉模型的识别质量。

`node scripts/verify_reading_rate_limit.mjs` 用最终 EXE 和隔离本地限流网关验收真实两秒间隔、
429 等待头、查询降级、取消、断点续建、重复更新不重发、有限重试及重启后恢复。
报告位于 `artifacts/reading-rate-verification`，不调用用户的真实付费服务。
