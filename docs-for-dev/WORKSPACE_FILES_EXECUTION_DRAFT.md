# 草稿文件与本地程序执行方案（草稿）

日期：2026-11-11

状态：待实施。本轮仅完成源码核对和方案；没有新增工具、开启执行权限或安装解释器。

## 目标

用户在普通对话、沉浸式阅读中说“把总结保存为 summary.md”“写一个
scripts/demo.py 并运行”，客户端应交付真实文件，并在获得执行权限后返回真实运行结果。
切换会话、页面刷新、重启客户端后，文件及执行记录仍能找到。

应用主体保持 Tauri 2 + Rust。写文件、版本管理、任务调度、存储和界面均由现有
Rust 服务与静态前端承担；运行 Python 脚本时才调用用户配置的外部解释器。
没有 Python 的机器仍可使用客户端其他功能，也可生成和下载 `.py` 文件。

## 源码中的现状

| 能力 | 当前实现 | 缺口 |
| --- | --- | --- |
| 创建可编辑总结 | `write_note` 与文档交付服务可保存应用内文档 | 不等于任意命名的 `.md`、`.py`、`.rs` 等工作区文件 |
| 浏览现有文件 | `workspace_list/read/search` | 没有正式的 `workspace_write`、版本冲突检查或补丁工具 |
| 展示文件 | `workspace_present` 可复制到上传目录并返回可预览、下载的文件项 | 需要与新建文件、版本和执行产物统一关联 |
| 执行源码 | `exec` 已支持 Python、C、C++、shell，默认关闭 | 每次写入固定入口，例如 `main.py`；不是按会话维护的程序项目 |
| 执行目录 | `data/exec_workspaces/<turn_id>/` | 下轮修改同一个文件、模块导入和跨轮运行缺少统一入口 |
| 执行限制 | 默认 30 秒、最多 300 秒；源码上限 2 MiB；每路输出截断到 128 KiB | 缺少完整的持久任务状态、用户取消与进程树清理验收 |
| 外部环境 | 使用用户系统 PATH，清空环境后设置白名单及便携路径；不捆绑解释器 | 需增加明确的解释器选择、相对路径配置和可用性检测 |

现有产物收集对 32 MiB 以上文件跳过哈希，不代表执行过程已有磁盘配额。
现有执行器属于进程隔离，不是操作系统级文件系统或网络沙箱；工作目录和代码关键词
检查不能阻止任意脚本访问其他目录。后续界面和文档必须如实描述这个边界。

对应实现：`src-tauri/src/server/exec_tool.rs`、
`src-tauri/src/server/tools.rs`、`src-tauri/src/server/tool_policy.rs`、
`src-tauri/src/server/workspace_data.rs`。

## 文件与便携存储

复用已经登记的内容工作区根目录，不把阅读资料组 ID 当作内容工作区 ID。
默认工作区托管根目录为安装目录下的 `data/workspaces/`；用户调整位置时仍限制在
便携根目录中。建议在所属工作区增加：

```text
<内容工作区根目录>/
  projects/<session_id>/
    files/                       # 用户可读写的当前文件
      summary.md
      scripts/demo.py
      results/summary.csv
    versions/<file_id>/           # 修改前的版本快照
    runs/<run_id>/                # 本次运行的输入快照、日志、产物清单
```

SQLite 保存相对路径、内容摘要、文件版本、来源会话及回合、所属阅读资料组、
创建时间等元数据。持久项目文件不放 `temp/`，也不因清理编译中间产物被删除。
解释器的缓存、HOME、临时目录继续使用安装目录的 `cache/`、`home/`、`temp/`；
Python 字节码缓存和可控的依赖缓存也显式指向便携目录。
第三方程序若有独立硬编码路径，检测到后明确说明，不宣称可完全重定向其所有写入。

对外展示文件卡片和相对路径；提供打开、下载及定位所在文件夹。对话删除、项目删除、
回收站和导出必须分别定义，不能因删除一条消息自动删除整个项目。

## 写入与修改工具

第一阶段提供以下工具，普通对话和阅读模式复用同一实现：

| 工具 | 输入与行为 |
| --- | --- |
| `workspace_write` | 相对路径、UTF-8 完整正文、预期版本；创建或原子替换一个文本文件 |
| `workspace_patch` | 相对路径、预期版本、精确替换项；不匹配则返回冲突并要求重读，不猜测修改位置 |
| `workspace_read/list/search` | 复用现有能力，增加会话项目与文件版本信息 |
| `workspace_present` | 复用文件预览和下载，关联 `file_id`、版本和来源任务 |

新文件不依赖执行权限。覆盖文件必须使用读取时获得的版本或 SHA-256；
用户手工编辑与模型并行写入时返回冲突。首次创建遇到同名文件也返回冲突。
写入采用同目录临时文件及替换流程，成功后再提交版本和产物事件；失败不能回答“已保存”。

路径检查覆盖盘符、UNC、设备路径、`..`、NTFS 备用数据流、符号链接及目录联接，
创建父目录和最终写入时均检查边界；以实际根目录为准，不依赖字符串前缀或提示词约束。
仅创建常规文件。执行中的输入文件使用不可变快照，用户继续编辑不会改变已启动任务。

模型提示明确区分“直接回答”“创建文件”“运行程序”：

- “解释这段代码”仍是普通回答。
- “写一个本地 py 文件”必须调用写入工具并返回文件卡片，不能只输出代码块。
- “写好并运行”先保存，再运行保存的确切版本，汇报文件路径、退出码和输出。
- “修改刚才的脚本再运行”读取当前版本、提交修改，并以新版本启动一个新任务。
- 失败时保留源码和诊断信息；修复后运行新版本，不把旧结果描述为新结果。

## 运行已保存文件

建议增加 `workspace_run`，与现有 `exec` 共用 Rust 执行服务，逐步统一日志、限制和产物收集；
不另起一套 shell 拼接执行器。

输入包含入口相对路径、文件版本、运行时配置 ID、参数数组、标准输入及超时。
后端用进程参数 API 直接传参。默认只运行所选入口，禁止借文件名或参数绕过工具调用任意命令。
初期支持 Python 和受控的 C/C++ 编译运行；shell 保持独立权限，其他语言按实际需求后续扩展。

在设置中配置系统解释器，或安装目录内用户自行放置的便携解释器，例如
`runtimes/python/python.exe`。相对路径便于整体迁移；绝对系统路径移动机器后重新检测。
运行前显示实际解释器、版本及不可用原因，不自动下载或安装依赖，不自动运行 `pip install`。
第一阶段建议只使用标准库或已存在的依赖，依赖管理单列后续任务。

写文件与执行分开授权：工作区文件写入在用户发出创建、修改请求后按任务执行；
本地执行沿用默认关闭的设置，可由用户针对工作区启用。启用后的授权按用户选择持续生效，
无需每次普通运行重复弹窗。没有执行权限时仍交付文件，并明确显示“尚未运行”。
第一阶段定位为可信本地脚本运行；需要强文件系统或网络隔离时，另行实现并验证 Windows
受限进程等机制，不能把当前 `exec` 的限制当作完整沙箱。

## 任务生命周期与恢复

运行记录与对话回合分别保存：

```text
queued → running → completed / failed / cancelled / timed_out / interrupted
```

每次写文件及运行都有幂等 ID。收到同一提交、WebSocket 重连或重放事件时返回原记录，
不重复覆盖文件或再次运行程序。运行期间持久保存日志游标、文件版本、参数、
解释器版本、退出码、耗时和产物哈希，不保存模型密钥。

切走页面继续后台执行，切回从已消费序号恢复输出；打开设置或刷新不取消任务。
“停止”同时取消回合与所关联的运行任务，并等待进程树退出。
Windows 优先使用可随任务关闭而终止进程树的 Job Object；超时和用户取消复用同一清理流程，
不能只终止父进程。客户端异常退出后把未完成运行标为 `interrupted`，
保留已写文件和日志，不静默重新执行带副作用的程序。

stdout、stderr 分开显示和限量保存，截断要有明确标记。限制运行时长、输出长度、
产物数量与磁盘占用；回收日志和缓存时保留用户文件。自动修复重试次数有明确上限，
每次关联新版本与新运行 ID，避免无休止循环。

## 界面交付

阅读模式沿用当前右侧文件查看器：

- 文本、Markdown、代码文件可预览，显示文件名、相对路径、版本、大小和保存状态。
- 代码文件提供打开、下载、编辑和运行入口；执行权限未启用时说明状态。
- 运行卡片显示排队、运行、完成等状态，提供停止、日志和输出文件。
- 文档继续使用现有文档编辑器；程序文件使用代码查看器，避免把 `.py` 当作文档正文。
- 历史会话再次打开时回读文件与运行元数据，过期卡片不能指向已被替换的其他版本。

## 实施顺序与验收

1. **文件交付**：补齐写入、补丁、版本及文件卡片。验收 `.md`、`.txt`、`.py`、
   `.json`、`.rs` 的真实落盘、中文路径、冲突和跨轮修改。
2. **运行保存的文件**：整合执行服务、解释器设置、日志与取消。验收 Python
   标准库脚本生成 CSV，源码与输出可下载；解释器缺失、语法错误、超时均有明确结果。
3. **恢复和边界检查**：验收切换会话、打开设置、刷新、断网、应用退出重启、
   双击提交和重放；同一运行不重复执行，取消不遗留子进程。
4. **便携交付**：搬动整个安装目录后继续读取项目、查看历史并调用相对解释器。
   验收所有受控缓存落在安装目录；更新 EXE/ZIP 保留既有项目和用户数据，发行包不混入
   测试项目、模型配置、Python、Node 或开发依赖。

本草稿建议先实现第 1、2 阶段，再按第 3、4 阶段的验收项交付；本轮不改变当前执行权限。
